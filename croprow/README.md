# croprow — single-class crop (lettuce) localization

Real-time localization of **where crop plants are** for a cultivator-mounted
camera: one class (`lettuce`), detection boxes, video inference with persistent
track IDs. This is **separate** from the potato disease-detection stack in
[`../ml/`](../ml/) — nothing here imports from or modifies it.

- **Single class only.** No weed and no disease classes.
- **Real data only.** No synthetic or AI-generated training images.
- **Public vs own data are never merged.** LettuceMOTS and your own-frame
  metrics are always reported as separate rows/tables.

## Dataset

[LettuceMOTS](https://drive.google.com/drive/folders/1HIoiyUOu4zYh8jHgqebnbZF_Ewn6Hq62),
downloaded **outside** this repo. Point to it with the `LETTUCE_ROOT` env var
or the config cell at the top of each notebook (default assumes
`D:\croprow_dataset\LettuceMOTS`). It is never committed.

Layout used by the notebooks (relative to `LETTUCE_ROOT`):

```
train/images/<seq>/<frame>.png      # video frames, per sequence folder
train/labels/<seq>/<frame>.txt      # YOLO boxes  (generated by notebook 01)
LettuceMOTSyolo/<seq>/<frame>.txt   # source labels: YOLOv5 seg POLYGONS
test/images/<seq>/<frame>.png       # frames with no labels (demo clips only)
```

The ground-truth labels are YOLOv5 **segmentation polygons**, not detection
boxes. Notebook 01 verifies this and derives one axis-aligned box per polygon
(min/max of its normalized vertices) — deterministic, from the real
annotations. If a future dataset ships real boxes, 01 detects that and passes
them through unchanged.

**Train/val split is by sequence folder**, never by frame: frames inside a
sequence are consecutive video frames, so a whole sequence goes entirely to
train or entirely to val (7 train / 2 val here). Random per-frame splitting
would leak near-identical adjacent frames across the split.

## Environment

Two Python environments, kept apart:

| env | Python | for |
| --- | --- | --- |
| `croprow/.venv` | 3.11, numpy<2 | everything here |
| `../.venv` | 3.13, numpy 2 | the potato backend — **leave untouched** |

```bash
py -3.11 -m venv croprow/.venv
croprow/.venv/Scripts/activate            # Windows
pip install -r croprow/requirements-train.txt
python -m ipykernel install --user --name croprow --display-name "Python 3 (croprow)"
```

Notebooks 01–02 need only numpy/opencv/matplotlib/pyyaml/jupyter; 03–07 add
torch + ultralytics (install the torch build matching your CUDA from
pytorch.org). A GPU is strongly recommended for training.

## Notebooks (`croprow/notebooks/`, run top to bottom)

| # | notebook | status | what it does |
| --- | --- | --- | --- |
| 01 | `01_dataset_prep`  | **run** | verify labels, split by sequence, polygon→box, emit `data/lettuce.yaml` (nc=1) |
| 02 | `02_verify_labels` | **run** | draw boxes on 20 random frames, inline |
| 03 | `03_train`         | ready   | train YOLO11n; config cell up top; logs to RESULTS.md |
| 04 | `04_finetune`      | unrun   | low-LR fine-tune on **your own frames** (set `OWN_DATA_YAML`) |
| 05 | `05_evaluate`      | ready   | LettuceMOTS-val and own-frames metrics, **separate tables** |
| 06 | `06_detect_video`  | ready   | detect + ByteTrack IDs + live FPS → annotated mp4; ffmpeg sequence→mp4 helper |
| 07 | `07_speed`         | ready   | ONNX + TensorRT FP16 export; benchmark imgsz 640/512/416 |

01 and 02 are already executed (outputs saved in the notebooks). 03–07 ship
**unrun** — whoever trains runs them; they stop with a clear message if weights
or your frames are missing rather than fabricating a fallback.

## Speed target

**≥ 30 FPS end-to-end.** FPS in 06/07 is measured with a real timer around the
**full** loop — frame read + inference + tracking + draw — not the model call
alone. 07 flags any config that misses the target honestly.

## Results

Every run appends a row to [`RESULTS.md`](RESULTS.md): mAP50, mAP50-95,
precision, recall, epochs, imgsz, and which dataset.
